# FAX OCR リネーマー（完全オフライン）

あなたは自動ファイル処理エージェントです。
以下の運用ルールを厳守してください。
質問や提案は一切行いません。

与えられた条件のみに基づいて、ファイルリネームを決定・実行します。

---

## システム構成（完全オフライン）

**外部APIは使用しません。**

| コンポーネント | 実装 |
|---------------|------|
| OCR | PaddleOCR (Docker) |
| LLM整形 | LM Studio (ローカル) |
| リネーム | Node.js ルールベース |

**前提条件:**
```bash
# PaddleOCR API を起動（初回のみ）
docker-compose up -d
```

---

## 運用ルール（厳守事項）

### 0. 実行前の確認（最優先）

**処理を開始する前に、必ず以下を確認・報告する:**

| 確認項目 | 説明 |
|---------|------|
| 処理モード | バッチ / 差分 / 監視（Watch） |
| 対象フォルダ | 入力フォルダのパス |
| 対象ファイル数 | 処理対象のファイル数 |
| 出力先 | 出力フォルダのパス |

**確認フォーマット:**
```
═══════════════════════════════════════
処理開始前の確認
═══════════════════════════════════════
📁 処理モード: [バッチ / 差分 / 監視]
📂 入力: /path/to/input (XX件)
📂 出力: /path/to/output
🔧 オプション: --searchable-pdf --llm-rename --apply-rename
═══════════════════════════════════════
```

**処理モードの違い:**

| モード | 用途 | コマンド |
|--------|------|---------|
| バッチ | 全ファイル一括処理 | `node src/main.js --in ./input --out ./output` |
| 差分 | 未処理ファイルのみ | OCR/Searchable PDFが無いファイルのみ処理 |
| 監視 | リアルタイム監視 | `node src/watch.js "/path/to/folder" ./output` |

### 1. リネーム提案の取り扱い

- リネーム提案が生成された場合、**常に採用する**
- 確認を求めない
- 提案名を変更しない

### 2. ファイルリネームの動作

- リネームは**既存ファイル名を上書き**する形で実行
- 重複ファイルを作成しない
- 旧ファイル名を残さない
- コピーやバックアップを作成しない

### 3. Searchable PDF の取り扱い

- 入力ファイルが既にSearchable PDF（テキスト検索可能）の場合:
  - OCRを実行しない
  - PDFを再生成しない
  - **ファイル名リネームのみ**を実行

### 4. 処理スコープ

- メタデータを追加しない
- ファイルを他のディレクトリに移動しない
- 上記ルールで明示的に必要な場合を除き、ファイル内容を変更しない

### 5. 失敗時の取り扱い

- リネームが不可能な場合、処理を停止し失敗を報告する
- 代替アクションを試みない

### 6. 必須の処理報告（厳守）

**処理完了時は必ず以下を報告する:**

| 項目 | 報告内容 |
|------|----------|
| Searchable PDF | 生成した件数 / スキップした件数 / エラー件数 |
| リネーム | 実行した件数 / スキップした件数 / エラー件数 |
| エラー詳細 | エラーがあれば、ファイル名と理由 |

**報告フォーマット例:**
```
═══════════════════════════════════════
処理結果レポート
═══════════════════════════════════════
✅ Searchable PDF生成: 15件
✅ リネーム実行: 15件
⏭️  スキップ（既存）: 5件
❌ エラー: 1件
  - filename.pdf: PNG not found
═══════════════════════════════════════
```

### 7. Searchable PDFの必須生成

- **全てのPDF処理でSearchable PDFを生成する**
- `--searchable-pdf`オプションは常に有効にする
- OCRのみでSearchable PDFを生成しない処理は禁止

---

## 実行フロー

```
1. 入力ファイルを受け取る
2. Searchable PDF かどうかを判定
   - YES → ステップ 6 へスキップ（リネームのみ）
   - NO → ステップ 3 へ
3. OCR を実行（PaddleOCR / ローカル）
4. .ocr.json を生成
5. Searchable PDF を生成（必須）
6. .rename.json を読み取り
7. リネーム提案を **無条件で採用**
8. ファイルをリネーム（上書き）
9. **処理結果を報告**（必須）
```

## コマンド例

### 基本実行（自動リネーム）

```bash
# 単一ファイル処理
node src/main.js process \
    --in "{入力ファイル}" \
    --out "./output" \
    --apply-rename

# フォルダ一括処理
node src/main.js \
    --in "./input" \
    --out "./output" \
    --apply-rename
```

### Searchable PDF 判定（事前チェック）

```bash
# PDFがテキスト検索可能かチェック
pdftotext "{入力ファイル}" - 2>/dev/null | head -c 100

# 出力あり → Searchable PDF（OCR不要）
# 出力なし → 画像PDF（OCR必要）
```

### リネーム実行

```bash
# 提案ファイルからリネーム名を取得
suggested_name=$(cat "{出力フォルダ}/{ベース名}.rename.json" | jq -r '.suggested_stem')

# リネーム実行（上書き）
mv "{入力ファイル}" "{入力フォルダ}/${suggested_name}.pdf"
```

### Watchモード（リアルタイム監視）

フォルダを監視し、新規/変更ファイルを即座に処理する。
バッチ処理と異なり、処理中にファイルが追加されても検出可能。

```bash
# FAX1NEWフォルダを監視（起動時に既存ファイルもスキャン）
node src/watch.js "/path/to/FAX1NEW" ./output/watch

# 既存ファイルをスキップして監視のみ
node src/watch.js "/path/to/FAX1NEW" --no-scan
```

**Watchモードの特徴:**
- 新規PDFファイルを即座に検出・処理
- `YYYYMMDD_`で始まるファイルは自動スキップ
- ファイル書き込み完了まで2秒待機（部分ファイル防止）
- Ctrl+C で終了

## ファイル名フォーマット

```
{日付}_{伝票の種類}_{送り先}_{内容}.pdf
```

### フォーマット詳細

| 要素 | 説明 | 例 |
|------|------|-----|
| 日付 | 文書の日付またはFAXヘッダーの日付（YYYYMMDD形式） | `20251203` |
| 伝票の種類 | 見積依頼、見積書、注文書、請求書、納品書など | `見積依頼` |
| 送り先 | 宛先の会社名（社員名は除外） | `有限会社ツダ` |
| 内容 | 材質、品目数、図番など（あれば） | `SS400_14品目` |

### 例

- `20251203_見積依頼_有限会社ツダ.pdf`
- `20260115_注文書_株式会社山田工業_SS400_5品目.pdf`
- `20260120_請求書_株式会社佐藤製作所.pdf`

## 社員名除外リスト

**以下の社員名・役職は送り先として採用しない：**

| 名前/役職 | 理由 |
|----------|------|
| 荻田 | 社員名 |
| 酒井 | 社員名 |
| 真鍋 | 社員名 |
| 中西 | 社員名 |
| 社長 | 役職 |
| 専務 | 役職 |
| 部長 | 役職 |
| 課長 | 役職 |
| 係長 | 役職 |

FAX文書では、これらの名前が宛先に記載されていることがあるが、
**取引先の会社名を優先して採用する**。

## 電話番号の除外

**以下の電話/FAX番号は伝票番号として採用しない：**

- `06-6482-3054` - 日興金属FAX番号
- その他、電話番号形式（`00-0000-0000`）のもの

## 書類種別の揺らぎ対応

FAX文書では口語的な表現が使われることがある。
これらを正式な書類名に正規化する：

| 口語表現 | 正規化 |
|---------|--------|
| 見積もりお願い | 見積依頼 |
| 価格ください | 見積依頼 |
| お見積りお願い | 見積依頼 |
| ミルシートください | ミルシート依頼 |
| ミルシートお願い | ミルシート依頼 |
| 手配お願い | 発注依頼 |
| 手配ください | 発注依頼 |
| 注文します | 注文 |
| 注文お願い | 注文 |
| 発注お願い | 発注依頼 |

## FAXヘッダーの日付

FAXヘッダーには送信日時が含まれることが多い。
文書本体に日付がない場合、FAXヘッダーの日付を採用する。

対応形式：
- `2024/01/30 14:35`
- `2024-01-30 14:35`
- `01/30/24 14:35` (短縮年形式)

## ミルシート（鋼材証明書）リネームルール

ミルシートは特別なルールでリネームする。

### ファイル名形式

```
{発行日付}_{材質}_{厚み}_{メーカー名}_{チャージ番号}.pdf
```

### 例

- `20240411_SS400_9t_中山製鋼所_48D7503.pdf`
- `20230510_SS400_9.00t_東京製鉄_AD3898.pdf`
- `20241015_SM400B_12t_JFEスチール_JL7JU6Y73.pdf`

### 各項目の抽出ルール

| 項目 | ルール | 例 |
|------|--------|-----|
| 発行日付 | ミルシート本体の発行日（Date of Issue）を採用。**ハンコ/スタンプの日付は採用しない** | `20240411` |
| 材質 | JIS規格の材質記号 (SS400, SM400A/B/C, SN400, SPHC, SUS304等) | `SS400` |
| 厚み | 寸法表記（9×1524×3048）の**最初の数字 + t** | `9t` |
| メーカー名 | **製造元を採用**（商社は採用しない） | `中山製鋼所` |
| チャージ番号 | 製鋼番号/溶鋼番号/鋼番 | `48D7503` |

### 重要：製造元 vs 商社の区別

| 製造元（採用する） | 商社（採用しない） |
|-------------------|-------------------|
| 東京製鉄 | 小野建 |
| 中山製鋼所 | 中山通商 |
| JFEスチール | 岡本鋼材 |
| 神戸製鋼所 | 阪和興業 |
| 日本製鉄 | 日興金属 |

### チャージ番号の形式（メーカー別）

| メーカー | 形式 | 例 |
|---------|------|-----|
| 中山製鋼所 | 数字2桁+英字+数字4桁 | `48D7503`, `38D4748` |
| 東京製鉄 | 英字2文字+数字4-5桁 | `AD3898`, `AE1276` |
| JFEスチール | 英数字混合 | `JL7JU6Y73` |

### 除外対象（ファイル名に含めない）

- 成分表データ (C, Si, Mn, P, S等)
- 商社の押印情報（日付・住所）
- 手書き/スタンプ

## 重要ルール: 自社名の除外

**「日興金属」「日興金属株式会社」「株式会社日興金属」は自社名のため、送り先として採用しない。**

FAX文書では、自社宛（日興金属宛）の文書が多い。この場合:
- 送り先 = 日興金属 → **除外**
- 代わりに **差出人（送信元）** を採用する

例:
- 「日興金属 御中」と書かれていても、送り先には採用しない
- 「株式会社〇〇より」の〇〇を送り先として採用

## テキストの意図を考慮したリネーム

OCRテキストを機械的に処理するだけでなく、文書の**意図**を理解してリネームする。

### 判断基準

1. **誰から誰へ送られた文書か？**
   - 差出人と宛先を特定
   - 自社宛なら差出人を優先

2. **何の目的の文書か？**
   - 見積依頼 → 価格確認したい
   - 注文書 → 発注したい
   - 請求書 → 支払い請求

3. **いつの文書か？**
   - 文書作成日または送信日を特定

## 禁止事項

| 行動 | 禁止理由 |
|------|----------|
| 確認を求める | 自動処理のため |
| 提案名を変更する | 一貫性のため |
| バックアップを作成する | 重複防止のため |
| 代替アクションを試みる | 明確な失敗報告のため |
| メタデータを追加する | スコープ外のため |
| ファイルを移動する | スコープ外のため |

---

## エラー時の動作

リネームが失敗した場合:

1. 処理を即座に停止
2. エラー内容を報告
3. 代替アクションは実行しない

```
[ERROR] リネーム失敗: {ファイル名}
理由: {エラー内容}
処理を停止しました。
```
